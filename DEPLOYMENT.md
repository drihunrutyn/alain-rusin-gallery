# Публикация GitHub Pages

Адрес: https://drihunrutyn.github.io/alain-rusin-gallery/

## Разделение веток

- `main` — действующее приложение Render. Серверные исходники в этой ветке не переключаются в рамках первой публикации Pages.
- `github-pages` — статическая витрина и подготовленный код будущей миграции кабинета.
- `.github/workflows/deploy.yml` в обеих ветках собирает **github-pages**, читает актуальный публичный каталог из Turso и публикует `out/` официальным Actions deployment.
- Push в `main` или `github-pages` запускает сборку. Ручное обновление: Actions → Deploy static storefront → Run workflow, ветка main.

Pages Source: GitHub Actions. Окружение `github-pages` разрешает ветку `github-pages`. Секреты `DATABASE_URL` и `DATABASE_AUTH_TOKEN` хранятся зашифрованными в GitHub Actions и не входят в экспорт. GitHub PAT используется локально для настройки, не публикуется и не нужен шагу deployment.

## Важно

Публичные изменения через существующий кабинет Render сохраняются в Turso. После них пока нужно вручную запускать workflow: текущая серверная версия Render не заменялась и ещё не вызывает новый rebuild helper. Подготовленный helper и ручной ввод заявок находятся в ветке `github-pages`, но не развёрнуты на Render. Не сливайте всю эту ветку в main без отдельной проверки переключения кабинета.

Письма/VK с витрины отправляет сам посетитель; нажатие кнопки не записывает заявку. Подписка и просмотры продолжают обращаться к Render. Каталог, фильтры, страницы картин, примерка и PDF работают по статическим данным без серверного чтения каталога.

Не публикуйте локальные `.env`, `.build`, `out` с тестовыми данными или базу QA. Не запускайте seed/schema-команды над действующей базой ради сборки.

## Проверки перед публикацией

```sh
bun install --frozen-lockfile
bun run test:static
bun run lint
npm run build
```

Сборка требует действующие Turso credentials в единственной корневой `.env`. Без них она падает, а не подставляет сид-данные. Содержимое БД не изменяется. В экспорт входят только работы, контент, комнаты и публичные настройки email/city. Заявки, подписчики, история просмотров и auth settings не экспортируются.

## Откат

Вернуть исправленный/предыдущий исходный commit ветки `github-pages` через обычный git revert и push. Новый workflow пересоберёт публичный каталог из текущей базы; это не исторический снимок БД. Ошибка build не заменяет предыдущую успешную публикацию Pages. Render остаётся независимым на main. Ничего в Turso не очищать.

Короткий путь `alain_rusin` можно настроить позже. Домен github.io содержит имя аккаунта; убрать `drihunrutyn` без отдельного аккаунта/организации или собственного домена нельзя.

Состояние первой публикации и проверенный URL сообщаются отдельно после завершения GitHub Actions; наличие workflow или принятого dispatch ещё не означает, что сайт работает.
