## Добавочная миграция серий
Единственная корневая `.env`: `DATABASE_URL`, отдельный write `DATABASE_MIGRATION_AUTH_TOKEN`. Обычный `DATABASE_AUTH_TOKEN` для Pages должен оставаться read-only.
```sh
bun run packages/web/scripts/migrate-series.ts
```
SQL: `packages/web/drizzle/0001_series.sql`. Создаёт только `series`, добавляет четыре исходные серии с `ON CONFLICT DO NOTHING`; неизвестная серия существующей работы вызывает rollback. Повторный запуск безопасен. Не очищает и не сидирует работы, заявки, подписчиков или настройки.

Миграция выполнена 5 ноября 2026, повторный запуск проверен. До/после: 4 работы, 3 записи контента, 0 комнат, 0 заявок, 0 подписчиков, 101 просмотр, 0 записей admin_settings. Добавлено 4 серии. Это контрольный снимок счётчиков на момент миграции, не обещание неизменности после реальных посещений.

## Ветки и порядок выпуска
1. Проверить/закоммитить `github-pages`: тесты, lint, `build:admin`, production static build.
2. Push `github-pages`.
3. Точечные проверенные изменения сервера закоммитить и push в `main`. **Не сливать всю Pages-ветку.** Render обновляется автоматически; push `main` запускает Pages workflow.
4. Проверить Actions conclusion, live deploy Render, фактические сайт и вход в кабинет.
5. Повторный ручной Actions run без изменений должен показать `cache-hit=true` и пропущенный deploy.

## Расписание, ручной запуск и кеш
Workflow `deploy-pages.yml` в default branch `main`; checkout исходников `github-pages`. Cron `0 7,10,13,16 * * *` соответствует 10:00, 13:00, 16:00, 19:00 Москвы. GitHub может задерживать или пропускать расписание; точное время и длительность не гарантируются.

Ручной запуск: Actions → Deploy static storefront → Run workflow → `main`. После обычного сохранения в кабинете автоматического dispatch нет. Push в `main` запускает workflow; push в `github-pages` сам по себе — нет.

Snapshot содержит только публичные данные. SHA256 не зависит от `builtAt`; ключ `data-snapshot-<hash>-<source-tree>` меняется и при изменении исходников. Он сравнивается с маркером **последнего успешного deployment**, восстановленным по префиксу `storefront-published-`. Совпадение пропускает сборку, upload и deploy; чтение snapshot/тесты всё равно выполняются. Сначала deployment, затем `actions/cache/save@v4` с уникальным ключом run/attempt: сбой публикации не отмечает данные как опубликованные. Возврат данных A → B → A корректно публикует A заново. Кеш может быть вытеснен GitHub — тогда безопасно выполняется повторная сборка.

Permissions: `contents: read`, `pages: write`, `id-token: write`. Секреты workflow: только `DATABASE_URL`, `DATABASE_AUTH_TOKEN`; PAT не используется. Окружение `github-pages` разрешает branch `main`. Группа concurrency `storefront-pages`, `cancel-in-progress: false`.

## Проверки
```sh
bun install --frozen-lockfile
bun run test:static
bun run lint
bun run build:admin
bun run build
```
На ветке `main`: `bun run --cwd packages/web build` и `bun run lint`. Для QA используется изолированная SQLite, без копирования private records. Не публиковать `.env`, QA-базу, токены, логи, `.build` или тестовый `out`.

Проверять: политику/согласие, фильтры/серии, PDF, видео, мобильную ширину, 404, `/api/health`, login, сохранность работ и доступа. Live QA не создаёт тестовые заявки/подписчиков.

## Откат
Откат исходников `github-pages` через git revert и ручной Actions run; прошлый неуспешный build не заменяет рабочие Pages. Каталог при пересборке читается из текущей БД, это не восстановление исторического снимка данных. Маркер сравнивается только с последней публикацией, поэтому возврат к более ранней версии не блокируется историческим кешем.

Render: redeploy прежнего проверенного commit только в существующем сервисе. Таблицу `series` оставьте — добавочное изменение не мешает прежнему коду. **Не удалять серии/работы и не восстанавливать всю БД ради отката кода.**

## Ограничения
Политика опубликована дословно по решению владельца, но её утверждения об отсутствии хранения данных не соответствуют активной подписке, заявкам и внешним сервисам. Подробности в README. Плееры требуют публичного доступа/разрешения embed на стороне платформы. Бесплатный Render может засыпать; статическая витрина от его чтения каталога не зависит.
