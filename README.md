# Alain Rusin — статическая витрина и закрытый кабинет

Миграция существующей галереи без смены стека: Bun, Vite, React, Hono, Drizzle, Turso и Tigris. Публичная витрина собирается для GitHub Pages; кабинет и небольшие API подписки/просмотров остаются на Render.

Ветка `github-pages` содержит статическую витрину. Ветка `main` сохраняет существующее приложение Render; сервер не переключается при первой публикации. Workflow `deploy.yml` всегда собирает `github-pages`. Каталог читается из действующей Turso во время сборки; первый deployment проверяется отдельно по результату Actions.

## Что меняется

- `npm run build` читает публичные работы, контент, комнаты и только настройки `email`/`city` из Turso **во время сборки**. Не запускает сидирование или миграции. При отсутствии `DATABASE_URL` сборка падает, а не подставляет тестовый каталог.
- `out/` содержит готовый HTML для `/`, `/gallery/`, `/about/`, `/media/`, `/b2b/`, `/privacy/`, каждой `/artwork/<id>/`, а также `404.html`, sitemap, robots и `.nojekyll`.
- Браузер фильтрует встроенный каталог локально. API чтения каталога и API автоматического создания заявок удалены. `/admin` и `/api` в экспорт не входят.
- Кнопки заявки открывают письмо или VK с названием, размерами и контактом. **Пользователь должен отправить сообщение сам.** Нажатие не сохраняет заявку в базе и не гарантирует отправку. Поддержка предзаполнения VK зависит от клиента VK.
- Заявки вручную создаются в защищённом кабинете; название картины выбирается из базы. Статусы: `new`, `in_progress`, `sold`, `cancelled`. Старый `processed` показывается как `in_progress` без массового изменения истории.
- Подписки и просмотры продолжают обращаться к Render. При его холодном старте они могут задерживаться; сам каталог открывается независимо. История заявок, подписчиков и просмотров не экспортируется.
- После изменения публичных данных кабинет запрашивает пересборку GitHub Actions. Ошибка пересборки не отменяет сохранение данных; кабинет показывает предупреждение. Принятый dispatch — не подтверждение завершённой публикации.
- Render после переключения обслуживает кабинет/API/общие ресурсы; публичные маршруты перенаправляет на Pages временным 302.

## Сборка и проверки

```sh
bun install --frozen-lockfile
bun run test:static
bun run build:admin
# Корневая .env должна содержать DATABASE_URL и DATABASE_AUTH_TOKEN.
npm run build
```

`build:admin` сохраняет production-сборку для Docker/Render. Dockerfile и управляемые `__*` файлы не менялись. `build:all` — прежняя сборка монорепозитория. Статическая сборка использует существующие исходные изображения и шрифты; новые картины не генерируются. PDF загружается лениво; Vite предупреждает о размере PDF-чанка.

Локальная разработка: единственная корневая `.env` по `.env.example`, затем `bun run dev` на назначенном шаблоном порту. Для **существующей** Turso не запускайте `db:push`, сидирование или очистку ради этой миграции.

## Публикация и дальнейшее переключение

Подробные шаги, переменные и откат: [DEPLOYMENT.md](DEPLOYMENT.md).

1. Pages использует GitHub Actions и зашифрованные секреты Turso; публичный репозиторий соответствует бесплатному плану.
2. Push в `github-pages` запускает сборку витрины; код Render в main не меняется.
3. После редактирования публичных данных в нынешнем кабинете вручную запустите Actions → Deploy static storefront → Run workflow.
4. Подготовленный новый кабинет и его rebuild helper находятся только в `github-pages`: эта часть ещё не развёрнута на Render. Перед отдельным переключением отключите Auto-Deploy Render, проверьте код и настройте серверный `GITHUB_REBUILD_TOKEN`.
5. Не сливайте всю ветку `github-pages` в main только ради обновления витрины.

## Авторизация и безопасность

Существующая авторизация сохранена: HTTP-only cookie, проверка сессии и источника административных запросов, смена пароля с Argon2id и отзывом сессий. Публичной регистрации нет. Каждая процедура `management` требует сессию. Публичные бизнес-API: `gallery.subscribe`, `gallery.view`; проверка сессии кабинета — `auth.me`.

Ключи Turso, Tigris, GitHub и данные сессий не имеют `VITE_`-префикса. `GITHUB_REBUILD_TOKEN` читается только сервером. Необязательный `NEXT_PUBLIC_BUILD_HOOK_URL`, несмотря на историческое название, тоже читается только сервером; предпочтителен ограниченный GitHub token. Telegram-уведомления не используются.

## Редакционные ограничения

Часть исходных иллюстраций — фрагменты предоставленного триптиха, а не подтверждённые фотографии всех оригиналов. До продаж загрузите подтверждённые фотографии через кабинет. Сведения о наградах и членстве предоставлены владельцем, независимая проверка не проводилась.

`/privacy` не является юридически проверенной политикой. До публичного сбора персональных данных владелец должен предоставить и утвердить полный текст. Изменение контактов в настройках влияет на PDF; адрес получателя заявки и VK заданы в `src/web/lib/site.ts`.

`supabase/schema.sql` — историческое приложение к исходному ТЗ, не активная база. Эта миграция не переводит данные в Supabase и не создаёт платных ресурсов.
